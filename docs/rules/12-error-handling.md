# 에러 처리

담당자: 김서현

API 에러와 화면 오류를 어디서 처리하고 보여 주는지 정한다. 에러 응답 형식은 `10-api-contract.md`를 따른다.

## 역할 분담

| 처리하는 곳                                | 맡는 에러                           | 보여 주는 방법                                 |
| ------------------------------------------ | ----------------------------------- | ---------------------------------------------- |
| `apiClient` 인터셉터 (`src/api/client.ts`) | 401, 네트워크 오류, 타임아웃, 5xx   | 401은 refresh 후 재시도, 그 밖에는 전역 토스트 |
| 화면 (`features/<기능>`)                   | 400, 403, 404, 409 같은 업무 에러   | 폼 칸 아래 문구, 화면 안 안내                  |
| `ErrorBoundary`, `RouteErrorPage`          | 렌더링 중 던져진 예상하지 못한 오류 | `ErrorScreen` 전체 화면                        |

- 한 에러는 한 곳에서만 보여 준다. 인터셉터가 토스트를 띄운 에러를 화면에서 다시 토스트로 띄우지 않는다.

## 인터셉터

- 실패한 요청은 모두 `ApiRequestError`로 바꿔서 던진다. 화면은 axios 에러 모양을 직접 다루지 않는다.
- 401이면 토큰을 refresh하고 원래 요청을 다시 보낸다. refresh도 실패하면 로그아웃하고 `/login`으로 이동한다.
- 네트워크 오류, 타임아웃, 5xx는 `notify.error(message, { traceId })`로 전역 토스트를 띄운다.
- 400, 403, 404, 409는 토스트를 띄우지 않고 화면으로 넘긴다.

## 화면

- 에러 종류는 `error.data?.code`로 나눈다. `message` 문자열을 비교해서 나누지 않는다.
- 폼 입력 에러는 해당 칸 아래에 보여 준다. 서버 에러를 칸에 붙일 때는 react-hook-form의 `setError`를 쓴다.
- 조회 실패처럼 화면 안에서 안내할 때는 서버가 보낸 `message`를 보여 준다.
- 401 처리, 로그아웃, 로그인 화면 이동을 화면 코드에서 다시 구현하지 않는다.

```ts
const { mutate } = useCreateMember({
  mutation: {
    onError: (error) => {
      if (getApiError(error)?.code === 'MEMBER_DUPLICATE_LOGIN_ID') {
        setError('loginId', { message: getApiError(error)?.message })
      }
    },
  },
})
```

## 전체 화면 오류

- 렌더링 중 처리하지 못한 오류는 `ErrorBoundary`(라우트 밖)와 `RouteErrorPage`(라우트 안)가 받아서 `ErrorScreen`으로 보여 준다.
- 화면에서 처리할 수 있는 API 에러를 일부러 던져서 전체 화면 오류로 만들지 않는다.

## traceId

traceId는 사용자가 문의할 때 BE 로그에서 해당 요청을 찾기 위한 값이다. 사용자가 스스로 해결할 수 없는 오류에만 보여 준다.

| 에러                               | traceId                                       |
| ---------------------------------- | --------------------------------------------- |
| 400, 403, 404, 409 같은 업무 에러  | 보여 주지 않는다. `message`만 보여 준다.      |
| 네트워크 오류, 5xx, 전체 화면 오류 | 전역 토스트와 `ErrorScreen`에 작게 보여 준다. |

- traceId는 "문의할 때 전달할 오류 번호"처럼 용도를 알 수 있게 표시하고, 본문 메시지보다 눈에 띄지 않게 한다.
- traceId를 FE에서 만들거나 임의 값으로 채우지 않는다. 서버 응답에 없으면 보여 주지 않는다.
- 에러 코드와 traceId 읽기는 `getApiError(error)`로 한다.
